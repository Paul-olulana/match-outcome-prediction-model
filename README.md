## Overview
This repository predicts match outcomes (Home Win / Draw / Away Win) for French **Ligue 1** fixtures. It combines **FBref** and **Understat** data, **rolling-form** features, and a **calibrated Random Forest** classifier to produce probabilities that can feed directly into a Power BI dashboard and scouting reports.

**Highlights**
- Orchestrated notebooks for EDA, preprocessing, and model evaluation.
- `fa_scripts/` package with reusable preprocessing, inference, and Power BI export utilities.
- **Calibrated probabilities** with **draw-threshold** logic for reliable decision support.
- Production-ready artifacts: `champion_calibrated.joblib`, `model_card.json`, and dashboard-ready CSVs.

---

## What Is Match Outcome Modeling?
Match outcome modeling estimates the probabilities of each result in a football match based on historical performance. Unlike raw score prediction, it focuses on categorical outcomes **plus probability calibration** so analysts can:
- Quantify risk (e.g., probability of a draw) for betting or strategy.
- Combine model outputs with expert priors or Elo ratings.
- Translate model confidence into business-facing dashboards.

## Data Dictionary

| `home_gf_sum_l3`, … | float | Rolling sums of goals/cards/clearances |
| `away_*` | float | Mirror of home features for the away team |
| `*_diff` | float | Home minus away differentials (`add_differentials` in `fa_scripts/preprocess.py:200`) |
| `is_home` (team rows) | int | Indicator used before pivoting |
| `p_home_win`, `p_draw`, `p_away_win` | float | Calibrated prediction probabilities (`fa_scripts/infer.py:166`) |
| `confidence` | float | Max probability before draw override |
| `pred_label` | int | Final prediction after draw override |
| `pred_symbol` | string | Human-friendly label (H/D/A) |

## Data Quality & Assumptions
- **Canonical team names required**; update `TEAM_MAP` when new aliases appear (`fa_scripts/name_map.py:42`).
- **Date coverage** must be consistent across FBref/Understat exports; EDA notebook flags gaps.
- **xG availability** – fallback logic handles missing Understat metrics by using goal-based rolling stats (`fa_scripts/infer.py:74`).
- **No same-match leakage** – rolling features shift one match back before aggregation.
- **CSV schema** – `fa_scripts/io.py:73` expects exact filenames; missing files raise blocking errors.

## Modeling Approach

### Design Principles
- **Chronological honesty** – strict train/val/test splits by season.
- **Feature transparency** – interpretable rolling stats and differentials.
- **Calibration-first** – probabilities that support draw decisions.
- **Production readiness** – scriptable preprocessing and inference.

### Model Choice
- `RandomForestClassifier` with class weights `{-1:1.0, 0:1.8, 1:1.0}` (`model_card.json`).
- Captures non-linear interactions between form metrics.
- Robust to correlated rolling windows.
- Wrapped in `CalibratedClassifierCV (isotonic)` for probability reliability.

### Preprocessing
- Rolling feature generation via `build_team_form` (`fa_scripts/preprocess.py:115`).
- Pivot to match-level and compute differential features (`fa_scripts/preprocess.py:168`).
- Feature selection excludes same-match stats (see `notebooks/model_evaluation.ipynb`).

### Splitting Strategy
- **Train:** Seasons 2021–2023  
- **Validation:** 2024 (used for model selection & calibration)  
- **Future Test:** 2025 reserved (no leakage yet)  
- Chronological split defined in `notebooks/02_preprocess_feature_engineering.ipynb`.

### Calibration
- Isotonic regression with `cv="prefit"` to calibrate the Random Forest on validation data.
- Draw override threshold (`tau_draw = 0.4368`) chosen via sweep (`notebooks/model_evaluation.ipynb`).

### Metrics
- **Log Loss** – 0.778 on validation (2024).  
- **Accuracy** – 0.667.  
- **Macro F1** – 0.583; **Draw recall** monitored separately (0.289).  
- **Brier Score** – 0.153 (derived from `Val_predictions_powerBI.csv`).

### Draw Handling
- Predictions below the confidence threshold revert to **draw** (see `fa_scripts/infer.py:166`).
- Draw override reduces overconfidence in low-signal fixtures, improving calibration.

## Pitfalls & Best Practices

### 🚫 Avoid
- Mixing seasons in chronological splits.  
- Training on same-match stats (stick to `_l*`, `_sum_*`, `_diff` features).  
- Ignoring team name canonicalization — it causes silent mismatches.

### ✅ Do
- Add new aliases to `TEAM_MAP` promptly (`fa_scripts/name_map.py:42`).  
- Recompute rolling form whenever raw data updates.  
- Monitor draw recall; adjust `tau_draw` after each retrain.  
- Document data refresh dates to align stakeholders.

## FAQ

**How do I adapt this model for a new league?**  
Update `TEAM_MAP`, supply league-specific raw CSVs, and re-run preprocessing notebooks. Adjust season splits in the notebooks.

**Can I change the draw override threshold?**  
Yes. Re-run the draw threshold sweep in `notebooks/model_evaluation.ipynb`, update `tau_draw` in `models/model_card.json`, and regenerate predictions.

**What if I’m missing Understat xG stats?**  
The inference pipeline backfills using goal-based rolling stats but expect reduced performance. Provide updated Understat exports and rebuild `team_rows_snapshot.csv`.

**Where do the Power BI CSVs come from?**  
`fa_scripts/predict_fixtures.py` writes predictions to `reports/dashboard/`. Validation predictions (`Val_predictions_powerBI.csv`) are exported during model evaluation.

**How do I score a single fixture programmatically?**  
Load the model bundle via `fa_scripts.infer.load_model_bundle`, build features using `build_features_for_fixtures`, and call `model.predict_proba` followed by `apply_draw_override`.
